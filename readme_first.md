## 三、任务理解

整个任务的背景非常清晰：如何在保障大模型厂商无法窃取数据的前提下，为企业用户提供大模型服务。

例如，对于某芯片制造厂商而言，芯片数据是其核心机密。如果无法保障数据安全，它就不敢使用外部的大模型服务。

### Q1：调研与现有方案分析

1. 借助GPT开展了一些调研工作，并分析了当前的相关研究。

2. 我对当前方案进行了分析，认为该方案无效，无法解决上述问题。核心原因是：从Prompt到隐变量存在直接映射关系，非常容易通过词表或其他简单手段进行反向映射和还原。不过，这并不影响我们继续开展一些有意思的探究，毕竟本任务书的核心在于拆解问题，以及分析相关的性能问题。

3. 尝试通过增加噪声干扰来缓解还原率过高的问题。但是不出所料，在还原率明显下降之前，方案的有效性就已经崩溃。这个实验实际上不需要运行模型，只需要对隐变量进行逆向还原即可完成。

4. 目前来看，大模型服务的数据安全是一个不可解的问题。其核心矛盾在于：大模型需要理解清晰的Prompt语义，才能进行有效推理；如果打乱语义，只能得到无意义的输出。这势必意味着大模型厂商可以获得相关语义。尽管目前很多厂商声称不会存储用户数据，但这只是一种口头的商务保障，并不能从技术上解决安全问题。

5. 目前来看，绝对安全的方法只能是由企业用户在本地部署大模型服务并完成推理。大模型厂商可以考虑将大模型软件和算力硬件打包，一同提供租赁服务。

### Q2：复现AI Infra小组的方案

1. 这部分并不复杂，特别是在AI能力的加持下，可以比较容易地完成相应改造。

2. 我本地学习使用了一个开源小模型MiniMind。该项目在GitHub上也比较受欢迎，因此我直接使用MiniMind开展实验。

3. 我将该小组的方案称为“分离模型”。

4. 对分离模型和原始模型进行了结果对比，两者输出的Token相同。

5. 根据要求，我又执行了GSM8K测试。前50道题中，原始模型和分离模型都只答对了1道题；所幸两者答对的是同一道题，正确率均为2%。MiniMind的模型能力相对较弱。题目要求的是跑通GSM8K，由于时间有限，我没有执行全部1000多道题。

6. 为了通过GSM8K测试集反映优化前后的有效性与还原率之间的关系，我又使用Qwen3-1.7B模型进行了一次实验，其正确率达到56%。

### Q3：探究分离模型下的性能优化手段

1. 整个任务的重点在Q3和Q4，这也是AI Infra重点关注的性能、效率与成本问题。

2. 题目分析：在本地完成Embedding后，一个词（或Token ID）会直接膨胀为一个5120维向量，信息传输量大幅增加。对于串行执行的任务而言，在传递隐变量时，云侧算力可能因为闲置而被浪费。

3. 一个显然的优化手段是采用流水线作业：当任务A的隐变量到达云侧并开始计算时，任务B的隐变量可以同时进行传输，依此类推。并发也需要控制并发数量，过度并发会影响SLO。

4. 在流水线作业的基础上，我进一步考虑了Prefill和Decode两个阶段的差异，可以对Prefill和Decode进行分离处理。

5. 题目限制了传输能力，即企业到云侧的距离为500公里、公网带宽为10 Gbps。这进一步引出了多任务并发发送时可能产生的传输拥塞问题。由于时间有限，我没有在这一部分继续展开。

6. 进一步地，我考虑在云侧设置一个调度器，由调度器根据SLO对云侧任务进行有效编排。我们的目标是在保障服务体验的基础上最大化QPS，其本质是一个线性规划问题。

7. 受硬件条件限制，仅使用一台笔记本电脑复现上述场景确实比较困难。例如，网络传输时延很难成为性能瓶颈，主要瓶颈仍然是笔记本本身的算力。

### Q4：数学建模、求解线性规划问题并推广至大模型场景

1. 本任务直接要求对Q3引出的线性规划问题进行数学建模。

2. TTFT和TPOT衡量单个请求的响应速度与生成流畅度；最大请求率衡量整个系统在保证体验的前提下能够承载多少任务。

3. 采用的基本方案是：使用Roofline模型估算单个云侧Batch的计算下限，再通过Token级离散事件模型模拟端到端调度。

4. 预测模型的输入包括模型参数、硬件参数和工作负载；输出包括QPS，以及该QPS下的TTFT和TPOT。

5. 对于Qwen3-32B + 8 × NVIDIA H20，在满足SLO的条件下——即4K上下文输入、TTFT ≤ 3 s、TPOT ≤ 100 ms——预测QPS约为0.97。此时，P95 TTFT为2.889 s，P95 TPOT为87.8 ms，云端资源负载为89.9%。

   核心瓶颈并不是隐变量的传输时延，而是4K的大上下文输入给Prefill带来的巨大压力。

6. 坦率地说，对这一实际生产场景直接进行建模和估算仍然比较困难。由于此前没有直接接触过GPU和模型等对象，缺乏足够的直观认识。因此，我又通过对抗式提问的方式，让GPT对相关结果进行了交叉验证。
