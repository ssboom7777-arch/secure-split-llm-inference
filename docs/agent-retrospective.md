# Agent协作复盘

## Agent提供的帮助

Agent主要承担了四类工作。第一，协助拆解任务书，将安全、架构、调度和容量规划分别转化为可以验证的问题。第二，快速实现MiniMind分割推理、Hidden State反演、共享链路、离散事件容量模型以及配套的一键脚本。第三，持续执行实验并将结论回写到README和原始JSON中。第四，在Qwen3-1.7B上补充正确性、GSM8K和噪声消融，使结论不只依赖MiniMind。

## Agent出现的问题

Agent早期对短时间容量实验过度解读，较短测试没有充分暴露CPU热态和尾部抖动；延长实验后，MiniMind可持续容量边界明显下降。Q4最初的排队近似也偏乐观，后续改为逐Token离散事件模拟。Qwen3第一次GSM8K分割实验错误地将System指令合并到User消息，导致前13题只有1题正确；检查逐题输出后停止无效实验，改用与原始评测相同的ChatML System/User模板，最终得到27/50。另一个问题是部分早期脚本依赖仓库外的MiniMind tokenizer，整理GitHub交付时才改为仓库内资产和自动下载。

## 人工纠偏方式

人工持续追问“是否真实执行模型”“数据放在哪里”“同一道题是否一致”“为什么预测与实测差异大”，迫使实验从概念验证走向可审计证据。对于性能问题，人工明确要求固定企业2卡/云端8卡、500 km/10 Gbps、单云执行槽和SLO约束，避免用不一致的条件比较。对于Q4，人工区分了单请求体验指标与系统容量，并要求同时报告预测假设和误差。对于Qwen3 GSM8K，人工提出用更强模型重跑，最终证明MiniMind低准确率主要来自模型能力而不是分割。

## 最终认识

Agent非常适合快速实现、自动化实验和整理证据，但其输出不能直接作为结论。关键结果需要检查实验条件、逐题输出、运行时长、随机性和证据边界。本项目中最有效的协作方式是：由人确定问题边界和验收标准，由Agent完成实现与重复实验，再由人针对异常结果提出反例和纠偏要求。
