# Agent 协作一页复盘

本项目围绕“数据不出企业”的大模型分割推理展开，从安全攻击与防护、基础分割推理、跨地域调度优化，延伸到给定模型、硬件和 SLO 的容量估算。协作方式不是让 Agent 一次性给出答案，而是由人持续收紧问题边界，Agent 负责实现、执行、记录，再根据异常结果共同修正。

## Agent提供的帮助

Agent 主要承担四类工作：拆解任务书，把安全、架构、调度和容量规划转化为可验证问题；实现 MiniMind 分割推理、Hidden State 反演、共享链路、离散事件容量模型及一键脚本；执行实验并把结论回写到 README 和原始 JSON；最后用 Qwen3-1.7B 补充正确性、GSM8K 和噪声消融，使结论不只依赖 MiniMind。

## Agent出现的问题

Agent 早期对短时容量实验过度解读，短测试没有充分暴露 CPU 热态和尾部抖动；延长实验后，MiniMind 可持续容量边界明显下降。Q4 最初的排队近似也偏乐观，随后改为逐 Token 离散事件模拟。Qwen3 首次 GSM8K 分割实验误将 System 指令合并到 User 消息，前 13 题仅答对 1 题；检查逐题输出后停止无效实验，改用与原始评测一致的 ChatML System/User 模板，最终得到 27/50。部分早期脚本还依赖仓库外 tokenizer，直到整理 GitHub 交付时才改为仓库内资产与自动下载。

## 人工纠偏方式

人工持续追问“是否真实执行模型”“数据放在哪里”“同一道题是否一致”“为什么预测与实测差异大”，推动实验从概念验证走向可审计证据。性能实验被统一到企业 2 卡/云端 8 卡、500 km/10 Gbps、单云执行槽和 SLO 约束，避免在不一致条件下比较。Q4 中，人工明确区分单请求体验指标与系统容量，并要求同时报告预测假设和误差。用更强的 Qwen3 重跑 GSM8K 后，也证明 MiniMind 的低准确率主要来自模型能力，而非分割本身。

## 最终认识

Agent 擅长快速实现、自动化实验和整理证据，但生成的解释不能直接当作结论。关键结果仍需检查实验条件、逐题输出、运行时长、随机性和证据边界。最终形成的有效闭环是：**人定义问题边界与验收标准 → Agent 实现并重复实验 → 人审查异常和提出反例 → Agent 修正模型、代码与文档**。这套闭环比一次性问答更可靠，也是本项目最重要的协作收获。
